# ミッションビンゴ 実装計画

1ステップずつ進め、完了条件をすべて満たしたら次へ進む。完了したステップは見出しの `[ ]` を `[x]` にする。

## [x] 0. セットアップ

Vite + React + TypeScript のプロジェクトを作り、`@cloudflare/vite-plugin`、Hono、Durable Objects のバインディングを設定する。

完了条件
- `npm run dev` でトップページが表示される
- `GET /api/health` が `{ "ok": true }` を返す
- `wrangler.jsonc` に `RoomDO` が `new_sqlite_classes` で登録されている

## [x] 1. RoomDO と WebSocket 同期

ルームIDごとに `RoomDO` を作り、WebSocket（Hibernation API）で接続を受けてメッセージを全員に配信する。この時点ではゲームロジックは入れない。

完了条件
- 2つのブラウザで同じルームに入り、片方の送信がもう片方に即時表示される
- 別ルームのメッセージは届かない
- リロード後に再接続し、RoomDO に保存した状態を受け取れる

## [ ] 2. 参加と識別

ルームコードで参加し、端末ごとのトークンで参加者を識別する。チームへの参加と GM の役割を扱う。

完了条件
- ルームコードを入れて参加でき、チームを選べる
- リロードしても同じ参加者・同じチームとして復帰する
- ルーム作成者が GM（GMありの場合）または操作主（GMなしの場合）になる

## [ ] 3. ルーム作成

spec.md「ゲーム設定」「ルーム作成」の設定項目、タスク入力、抽選、カード生成を作る。

完了条件
- カードサイズ（5×5 / 7×7 / 9×9）、FREE、チーム数（最大6・デフォルト3）、GM有無、カード形式、自動終了を設定できる
- 「あと◯個必要」が常に表示され、必要数未満では作成できない
- CSV / JSON（`title` 必須、`detail` 任意）で一括入力・出力できる
- 抽選は1回だけで、個別カードでも全チーム同じ並びになる。再接続しても同じカードが出る

## [ ] 4. プレイ画面と申請・承認

カード表示、詳細シート、チャット申請、GM の承認・却下、ビンゴ判定、順位、タイムラインを作る。画像申請はステップ8で追加する。

完了条件
- マスはタイトルのみ表示し、タップで詳細シート（タイトル・詳細・状態・申請ボタン）が開く。詳細が null なら非表示
- GMありでは申請時刻順に確認し、最初に承認された申請でマスが確定する。却下はコメント付きで返る
- GMなしでは申請と同時に取得する
- ビンゴ数と順位がリアルタイムに更新される
- 申請・承認・却下がタイムラインに時系列で表示される

## [ ] 5. GM 操作

マス取り消し、強制終了、個別カード時の全チームカード閲覧を作る。

完了条件
- 取り消しは理由必須。ビンゴ成立に関係なく取り消し、取り消し後の状態で順位を再計算する
- 取り消したマスに再挑戦できる
- 取り消しがタイムラインに残る（マス・チーム・理由・時刻）
- GM はいつでもゲームを終了できる
- 個別カードのとき、GM がタブで各チームのカードを切り替えて見られる

## [ ] 6. ゲーム終了と画面遷移

spec.md「ゲーム終了と画面遷移」の通りに作る。

完了条件
- 目標ビンゴ数到達・全マス埋まり（共有カードで自動終了ON）・GM の終了、いずれでも全員が結果画面へ自動移動する
- 結果画面の「カードを見る」から閲覧専用カードへ移れる。申請ボタンは出ず、上部にバナー、下部に「結果に戻る」ボタンがある
- ブラウザの戻るでも結果画面に戻る
- 終了済みルームへの申請・取り消しを RoomDO が拒否する

## [ ] 7. 共有カードの奪取と特別ミッション

spec.md「奪取ルールと特別ミッション」を作る。

完了条件
- GM（GMなしなら操作主）が特別ミッション（速さ / 量 / 質）を制限時間付きで発生させられる
- 1位のチームがビンゴ成立ラインを含む好きなマスを1つ奪える。同票なら1位全チームが1つずつ奪える
- 質タイプの全員投票で、自チームへの投票ができない
- 発生と奪取の結果がタイムラインに残る

## [ ] 8. 画像申請と R2

画像申請、R2 への保存、終了後3日での自動削除を作る。

完了条件
- お題ごとの「画像必須」設定が効き、画像付きで申請できる
- 画像は R2 に保存され、タイムラインと承認画面で見られる
- R2 のライフサイクルルールで3日後に削除される
- サイズ上限と圧縮方針は spec.md の未決事項が決まってから実装する

## [ ] 9. デプロイ

完了条件
- `npm run deploy` で本番 URL に公開され、別々の端末から1ゲーム通しで遊べる
